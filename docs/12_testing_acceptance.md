# 12. 테스트 및 수용 기준

## 1. 테스트 피라미드

1. 단위 테스트: 순수 계산/상태 전이/데이터 검증.
2. 통합 테스트: 서비스 간 흐름(인벤토리-제작, 건축-내비게이션 등).
3. 멀티플레이 테스트: 서버와 복수 클라이언트 동작.
4. 시나리오 테스트: NPC/쉘터/감염/사건 연쇄.
5. 성능 테스트: 활성 셀, NPC 수, 좀비 수, 네트워크 부하.
6. 장시간 테스트(soak): 저장, 메모리, AI 상태 정체, 서버 안정성.

## 2. 핵심 테스트 시나리오

### 2.1 생존
- 허기/갈증/피로가 시간/활동에 따라 변화.
- 부상에 따라 이동/작업/전투 성능 변화.
- 감염 진행과 치료 효과.

### 2.2 좀비
- 시야 내 플레이어 탐지.
- 소음 발생 후 조사.
- 시야 상실 후 마지막 위치 수색.
- 문/창/바리케이드 대응.
- 여러 좀비의 동일 소음 반응 최적화.

### 2.3 건축
- 자재 충분/부족.
- 유효/무효 위치.
- 동시 배치 요청.
- 파괴/수리.
- 방 인식 및 내비게이션 갱신.

### 2.4 NPC AI
- 욕구 충족 행동.
- 긴급 상황 인터럽트.
- 서로 다른 성격의 반응 비교.
- 비대칭 관계 저장.
- 기억 감쇠와 중요 기억 보존.
- 고정 seed 재현.
- 근거리/원거리 시뮬레이션 전환.

### 2.5 사회/사건
- 연애 상호 동의.
- NPC-NPC 관계 진행.
- 비밀 정보 공개 범위.
- 증거/목격 기반 조사.
- 범죄가 단일 감정값으로 발생하지 않음.

### 2.6 농업/가축
- 파종에서 수확까지.
- 계절/관수 영향.
- 생산/보관/부패.
- 가축 건강/먹이/생산.
- 좀비 공격/감염.

### 2.7 멀티플레이/저장
- 동시 루팅.
- 동시 건축.
- 연결 끊김 후 재접속.
- 서버 재시작 후 복구.
- 권한 없는 RPC 거절.
- 구역 스트리밍 후 상태 유지.

## 3. 성능 테스트 기준

초기에는 정량 목표를 임의로 확정하지 않는다. 테스트 장비/서버 사양을 먼저 명시하고 다음을 측정한다.
- 클라이언트 평균/1% low FPS.
- 서버 tick 시간과 최악 지연.
- 활성 NPC/좀비 수에 따른 AI 시간.
- 내비게이션 요청/갱신 시간.
- 네트워크 대역폭/지연/패킷 손실 시 동작.
- 저장/로드 시간과 파일 크기.
- 메모리 사용량 및 장시간 누수.

## 4. 버그 심각도

- P0: 저장 손실, 아이템 복제, 서버 권한 우회, 지속적인 크래시.
- P1: 주요 진행 차단, 치명적인 동기화 오류, 핵심 AI 정지.
- P2: 기능 일부 오작동/우회 가능.
- P3: 시각/사운드/경미한 UI 문제.

## 5. 완료 정의(Definition of Done)

- 요구사항이 구현되었다.
- 단위/통합/시나리오 테스트가 통과했다.
- 서버/클라이언트 역할이 검증되었다(해당 기능에 한함).
- 저장/복구 영향이 확인되었다.
- 로그/오류 처리가 있다.
- 문서가 구현과 일치한다.
- 미해결 이슈와 제한이 보고되었다.
