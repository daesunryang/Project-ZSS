# 11. UI/UX·아트·애니메이션·오디오 가이드

## 1. 비주얼 방향

세미 리얼리즘. 현실적인 재질, 조명, 건축 비례, 애니메이션을 사용하되 아이템/상호작용/상태는 읽기 쉽도록 대비와 실루엣을 확보한다.

## 2. 카메라

- 자유 회전 3인칭.
- 기본은 캐릭터 중심의 약간 높은 시점.
- 마우스/스틱으로 회전, 줌.
- 벽/지붕에 가려질 때 카메라 충돌 보정 및 가림 처리.
- 건축 모드에서 배치 정확도를 높이는 보조 시점 제공.
- 조준/전투 시 카메라 중심과 회전 속도를 별도 조정.

### 2.1 구현 현황 (P1-4)

- 마우스 입력으로 로컬 플레이어를 중심으로 yaw/pitch 자유 회전하는 3인칭 추적 카메라를 구현했다.
- 거리·피치 범위·마우스 감도는 `CameraSettings` Resource의 PROVISIONAL 값이다.
- 카메라 충돌/가림 처리, 줌, 건축 보조 시점, 조준/전투 전용 조정은 아직 구현하지 않았다.

### 2.2 구현 현황 (P2-N2)

- 서버 미러의 플레이어·좀비 위치와 yaw를 그대로 사용해 임시 캡슐을 표시한다. 좀비는 대기/조사/추격/공격/수색/휴면/사망 색을 구분하고, 사망한 좀비와 플레이어는 어두운 색으로 눕힌다. 보간·외삽·클라이언트 예측은 하지 않는다.
- HUD는 본인에게 복제된 체력·스태미나 수치, 허기/갈증/피로 범주(양호/주의/위험), 감염 단계, 상처 수와 출혈 여부, 사망 안내만 표시한다. 오프라인처럼 본인 미러가 없으면 생존 HUD를 숨긴다.
- 최근 근접 전투와 좀비 공격 이벤트를 제한된 줄 수로 표시한다. 감염 판정 결과는 본인을 대상으로 하고 서버가 해당 비공개 필드를 보낸 이벤트에만 표시한다.
- 기본 마우스 왼쪽 버튼은 카메라 yaw만 공격 의도로 보낸다. 피해·명중·체력·쿨다운 판정이나 공격 예측은 하지 않고, 서버의 승인/거부 결과를 잠시 HUD에 표시한다.
- 캡슐 크기·상태 색·사망 기울기·공격 버튼과 최소 전송 간격·HUD 표시 수/시간은 `ClientPresentationSettings` Resource의 PROVISIONAL 값이다.

### 2.3 구현 현황 (P2-T3 먹기·마시기)

- HUD 왼쪽(생존 상태 아래)에 인벤토리 요약을 표시한다: 들고 있는 묶음 수와 종류별 이름·합계 수량(설정된 종류 수까지, 나머지는 "외 N종"). 본인 인벤토리 미러만 쓰며 접속 전에는 숨긴다. 이름은 아이템 정의의 `display_name`이다.
- 소비 키(기본 F)는 인벤토리 미러의 첫 소비 가능 아이템 ID만 서버에 보낸다. 무엇을 얼마나 회복하는지는 서버가 정하고, 클라이언트는 욕구 변화를 예측하지 않는다. 서버의 승인/거부 결과(사유 코드)를 화면 아래 가운데에 잠시 표시하고, 소비할 것이 없으면 요청 없이 안내 문구만 표시한다.
- 아이템을 고르는 화면, 내려놓기 입력, 월드에 놓인 아이템의 표시는 아직 없다. 소비 키·최소 간격·표시 시간·요약 줄 수는 `ClientPresentationSettings`의 PROVISIONAL 값이다(docs/15 §11.1 P2-125).

### 2.4 구현 현황 (P2-T4 영구 사망)

- 생존 HUD 첫 줄에 "캐릭터 #N"을 표시한다. N은 서버가 본인에게만 보내는 세대 번호(같은 플레이어의 몇 번째 캐릭터인지)이며, 받기 전에는 줄을 만들지 않는다. 다른 플레이어의 세대 번호는 받지도 표시하지도 않는다.
- 사망 안내 문구는 "캐릭터가 끝났고 소지품은 죽은 자리에 남으며 잠시 뒤 새 캐릭터로 시작한다"는 내용이다(`ClientPresentationSettings.death_message`). 남은 대기 시간은 표시하지 않는다(서버가 보내지 않는다).
- 죽으면 인벤토리 요약이 "없음"이 되고, 새 캐릭터가 시작되면 캡슐이 스폰 지점으로 옮겨진다(보간 없음). 캐릭터 이름·외형·만들기 화면은 없다(docs/15 §11.2 P2-127, P2-128. P2-T9에서 생겼다, §2.8).

### 2.5 구현 현황 (P2-T6 붕대)

- 사용 키가 종류별로 나뉘었다(§2.3의 소비 키 하나를 대체): 음식 F, 물 G, 붕대 B. 각 키는 인벤토리 미러에서 그 종류의 첫 아이템 ID만 서버에 보낸다. 같은 종류 안에서 고르는 방법, 인벤토리 화면은 여전히 없다. 그 종류의 아이템이 없으면 요청 없이 "먹을 것이 없습니다/마실 것이 없습니다/붕대가 없습니다"를 표시한다.
- 생존 HUD 끝에 치료 줄이 붙는다: "출혈 중 (N곳) | 붕대 M개 [B]"(출혈이 없으면 "출혈 없음"). N은 본인 상처 미러의 출혈 상처 수, M은 인벤토리 미러의 붕대 합계, 대괄호 안은 설정된 붕대 키다. 기존 "상처 N | 출혈 있음/없음" 줄은 그대로 있다.
- 붕대를 쓰면 무슨 일이 일어나는지(어느 상처가 지혈되는지)는 서버가 정한다. 출혈이 없을 때 누르면 서버가 `not_bleeding`으로 거부하고 붕대는 줄지 않는다. 결과 문구는 "아이템 사용 승인" 또는 "아이템 사용 거부: 사유 코드"다.
- 줄 수가 늘어 생존 HUD와 인벤토리 요약 라벨의 세로 위치를 옮겼다. 실제 창에서의 배치는 확인하지 못했다(docs/15 §12.1). 키 3개는 `ClientPresentationSettings`의 PROVISIONAL 값이다(docs/15 P2-144).

### 2.6 구현 현황 (P2-T7 치료제)

- 치료제 키(기본 V)가 추가됐다. 인벤토리 미러의 첫 치료제 ID만 서버에 보내고, 없으면 "치료제가 없습니다"를 표시한다. 사용 키는 넷(음식 F, 물 G, 붕대 B, 치료제 V)이다.
- 생존 HUD의 치료 줄이 둘이 됐다. 둘째 줄: "감염: 단계 | 치료제 M개 [V]"(감염이 없으면 "감염 없음"). 단계는 본인에게만 복제되는 값이고, 기존 "감염 단계: …" 줄도 그대로 있다. 다른 플레이어의 감염은 받지도 표시하지도 않는다.
- 치료가 아직 듣는 단계인지는 HUD가 판단하지 않는다. 감염되지 않았을 때 누르면 서버가 `not_infected`, 단계가 지났으면 `too_late`로 거부하고 치료제는 줄지 않는다(사유 코드를 그대로 표시).

### 2.7 구현 현황 (P2-T8 수면)

- 휴식 키(기본 R) 하나로 눕기와 일어나기를 한다. 본인 미러가 "누워 있음"이면 일어나기, 아니면 눕기 의도를 보낸다. 실제로 눕는지는 서버가 정하고, 서버의 승인/거부 결과(사유 코드: `already_resting`, `not_resting`, `player_dead` 등)를 사용 결과와 같은 자리(화면 아래 가운데)에 잠시 표시한다.
- 생존 HUD 끝에 휴식 줄이 붙는다: 서 있으면 "눕기 [R]", 누워 있으면 "휴식 중 (피로 회복) | 일어나기 [R]". 죽은 캐릭터에게는 표시하지 않는다. 피로는 기존 줄의 범주(양호/주의/위험)로만 보이고 남은 휴식 시간은 표시하지 않는다.
- 누워 있는 플레이어의 캡슐은 본인이든 다른 플레이어든 옆으로 눕혀 바닥에 둔다. 색은 살아 있는 색 그대로라 어두운 색의 죽은 캡슐과 구분된다. 다른 플레이어가 누워 있다는 것은 서버가 공개하는 사실이고, 그 플레이어의 피로는 받지도 표시하지도 않는다.
- 누워 있는 동안 이동 키·공격·줍기·사용 키는 서버에서 거부되거나 무시된다(공격과 사용은 `player_resting` 사유가 결과 문구로 표시된다. 줍기는 결과를 표시하는 UI가 원래 없고, 이동은 응답 없이 캡슐이 움직이지 않는다). 피격으로 깨면 캡슐이 다시 서고 HUD 줄이 "눕기 [R]"로 돌아간다.
- 현재 키 배치(모두 설정값, PROVISIONAL): 이동 W/A/S/D, 줍기 E, 공격 마우스 왼쪽, 음식 F, 물 G, 붕대 B, 치료제 V, 휴식 R. 실제 창에서의 HUD 배치와 누운 캡슐의 모습은 확인하지 못했다(docs/15 §12.3).

### 2.8 구현 현황 (P2-T9 캐릭터 이름·외형)

- **캐릭터 생성 화면**(`scenes/ui/character_creation_screen.tscn`): 화면 가운데 패널에 제목, 안내 한 줄(첫 캐릭터인지 죽은 뒤인지에 따라 다르다), 이름 입력 칸과 길이 안내, 외형 항목마다 한 줄(항목 이름, 이전 ◀, 색 견본, 선택지 이름, 다음 ▶), 거부 사유 줄, "무작위"와 "만들기" 버튼이 있다. 항목 줄은 서버가 쓰는 것과 같은 외형 데이터에서 만들어지므로 데이터에 항목을 추가하면 줄이 생기고, 항목·선택지 문구도 데이터에 있다. 캐릭터 미리보기, 목록형 선택, 취소 버튼은 없다.
- 화면은 처음 접속했을 때와, 죽은 뒤 서버가 "새 캐릭터를 만들 수 있다"고 알렸을 때 뜬다. 떠 있는 동안 마우스 캡처가 풀리고 이동·공격·사용·휴식·줍기 입력은 보내지 않는다. "만들기"를 누르면 서버와 같은 규칙으로 이름을 먼저 검사해 틀리면 보내지 않고 사유를 표시하고, 맞으면 이름과 선택만 서버에 보낸다. 서버가 거부하면 사유를 문장으로 표시하고(모르는 사유 코드는 코드 그대로), 승인하면 화면이 닫힌다. 다시 열릴 때는 지난번 이름과 선택이 남아 있다.
- 이름 입력: 2~16자, 한글·영문·숫자·공백(서버 설정). 칸은 최대 길이까지만 받는다. Enter로도 확인한다.
- **월드 표시**: 아직 캐릭터 모델이 없어 외형은 임시 캡슐의 색과 크기로만 보인다. 상의 색 → 캡슐 색, 키 → 캡슐 높이, 체형 → 캡슐 반지름. **피부색, 머리 모양, 머리색, 하의 색은 고르고 저장·복제되지만 지금은 화면에 나타나지 않는다**(모델이 들어온 뒤 연결).
- **이름표**: 캐릭터 이름을 캡슐 위에 카메라를 향하는 글자(Label3D)로 표시한다. 본인은 하늘색, 다른 플레이어는 흰색, 죽은 캐릭터는 회색이다. 본인과 다른 플레이어를 캡슐 색으로 구분하던 것은 이름표 색으로 바뀌었다(캡슐 색은 이제 각자의 상의 색이다). 죽은 캡슐은 기존대로 어두운 색으로 눕고 이름은 새 캐릭터가 만들어질 때까지 남는다. 누워 쉬는 캡슐은 자기 색 그대로 눕고 이름표는 누운 캡슐 위에 뜬다. 거리 제한과 가림 처리는 없다.
- 생존 HUD 첫 줄에 본인 캐릭터 이름이 붙는다: "이름 | 캐릭터 #N". 사망 안내 문구는 "잠시 뒤 새 캐릭터를 만들어 다시 시작합니다"로 바뀌었다.
- `--character-name=<이름>`으로 시작한 클라이언트는 화면 없이 그 이름과 기본 외형으로 만든다(헤드리스 클라이언트, 빠른 시작).
- 이름표의 높이·글자 크기·색은 `ClientPresentationSettings`의 PROVISIONAL 값이다(docs/15 §13 P2-170). 실제 창에서의 화면 배치, 한글 글꼴, 이름표 가독성, 마우스 캡처 전환은 확인하지 못했다(docs/15 §13).

### 2.9 구현 현황 (P2-T10 수면 조정)

- 피로 범주가 주의·위험이면 생존 HUD의 휴식 줄 아래에 "피로로 작업 능력 저하 (주의)" 또는 "피로로 작업 능력 크게 저하 (위험)"이 붙는다(누워 있어도 표시). 서버가 보낸 피로 범주만으로 만든 문구이고 배율 수치는 표시하지 않는다. 허기·갈증은 이 줄과 무관하다.
- 자다가 저절로 깨면 이유를 사용 결과와 같은 자리에 잠시 표시한다: "공격을 받아 / 체력이 위험해 / 갈증이 심해 / 허기가 심해 / 감염이 악화되어 잠에서 깼습니다". 본인에게만 온 원인으로 만든다. 다른 플레이어가 깬 것은 캡슐이 일어서는 것으로만 보인다.
- 위험한 상태에서 눕기를 누르면 거부 사유를 문장으로 표시한다: "지금은 누울 수 없습니다: 체력이 너무 낮습니다 / 갈증이 위험합니다 / 허기가 위험합니다 / 감염이 너무 진행됐습니다". 그 밖의 거부는 기존대로 사유 코드를 표시한다.
- 키 배치는 §2.7 그대로다. 실제 창에서의 표시는 확인하지 못했다(docs/15 §14.1).

### 2.10 구현 현황 (P2-T11 엎드리기와 은신)

- 엎드리기 키(기본 C) 하나로 엎드리기와 일어서기를 한다. 본인 미러가 "엎드림"이면 일어서기, 아니면 엎드리기 의도를 보낸다(자는 중에 누르면 서버가 깨운 뒤 엎드린다). 실제로 바뀌는지는 서버가 정하고, 결과를 사용 결과와 같은 자리에 잠시 표시한다("자세 변경 승인" / "자세 변경 거부: 사유 코드").
- 생존 HUD 끝에 자세 줄이 붙는다: "자세: 서 있음 | 엎드리기 [C]", "자세: 엎드림 (은신 중) | 일어서기 [C]", "자세: 누워 잠 | 엎드리기 [C]". "은신 중"은 엎드려 있을 때만 나온다(자는 것은 은신이 아니다). 실제로 좀비에게 들켰는지, 얼마나 잘 보이는지는 표시하지 않는다(서버가 보내지 않는다). 죽은 캐릭터에게는 표시하지 않는다.
- 엎드린 플레이어의 캡슐은 본인이든 다른 플레이어든 앞으로 기울여(약 72도) 바닥에 붙인다. 뒤로 완전히 누운 자는 캡슐, 어두운 색으로 누운 죽은 캡슐과 구분된다. 이름표는 기운 캡슐 위에 그대로 뜬다(다른 플레이어에게는 숨지 않는다).
- 엎드려 있으면 이동 키로 느리게 긴다(서버가 속도를 정한다). 공격은 서버가 거부하고 "공격 요청 거부: 엎드린 채로는 공격할 수 없습니다"가 표시된다. 줍기와 사용 키(음식·물·붕대·치료제)는 엎드린 채로 된다.
- 현재 키 배치(모두 설정값, PROVISIONAL): 이동 W/A/S/D, 줍기 E, 공격 마우스 왼쪽, 음식 F, 물 G, 붕대 B, 치료제 V, 휴식 R, 엎드리기 C. 사용 키 넷·휴식 키·엎드리기 키는 서로 달라야 한다(설정 검증). 실제 창에서의 HUD 배치와 엎드린 캡슐의 모습은 확인하지 못했다(docs/15 §14.2).

## 3. UI 원칙

- 생존 상태는 HUD에서 빠르게 파악 가능.
- 세부 수치는 상태 범주/툴팁에서 제공.
- NPC의 기억/관계/비밀은 플레이어가 알아낸 정보만 표시.
- 건축 프리뷰는 유효/무효, 자재 부족, 충돌을 명확하게 표현.
- 경고는 중요도별로 계층화하고 화면을 과도하게 가리지 않는다.

## 4. 주요 화면

- HUD: 건강, 허기, 갈증, 피로, 체온, 감염 경고.
- 인벤토리/장비.
- 제작/레시피.
- 건축/청사진.
- NPC 목록 및 상태.
- 관계/가족/개인 사건 기록.
- 쉘터 관리 대시보드.
- 농장/가축 관리.
- 월드 지도 및 발견 정보.
- 사건/퀘스트/루머 기록.
- 서버 관리/설정(권한 기반).

## 5. 캐릭터 애니메이션

이동 방향/속도, 무기, 피로/부상, 상호작용 유형, 감정 표현을 고려한다. 근거리 NPC는 상세 애니메이션, 원거리 NPC는 저비용 표현으로 전환한다.

## 6. 오디오

- 3D 위치 기반 소리.
- 총성/경보/발전기/건축/문/차량 소리는 좀비 AI의 청각 시스템에 동일한 NoiseEvent를 생성한다.
- 날씨/실내외/거리/장애물에 따라 소리 표현을 조절한다.
- NPC 대화/감정/작업 사운드는 반복 피로를 줄이기 위해 변형과 빈도 제한을 둔다.

## 7. 접근성/사용성

- 키 재설정.
- 자막과 글자 크기 옵션.
- 색상만으로 상태를 구분하지 않기.
- 컨트롤러 지원은 PC 기본 입력 이후 확장.
- 중요 행동은 취소/확인 상태를 명확히 표시.
