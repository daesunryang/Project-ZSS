# 03. 월드·스트리밍·환경 명세

## 1. 목표

플레이어에게 하나의 연속된 대규모 세계를 제공하되 메모리, 렌더링, 물리, 내비게이션, AI 비용을 통제한다.

## 2. 월드 레이아웃

초기 후보 면적은 약 4km × 4km이며 확정값이 아니다. 다음 권역을 포함한다.

1. 도심: 병원, 마트, 아파트, 경찰서.
2. 주거지: 주택, 학교, 편의점, 주차장.
3. 농촌: 농장, 축사, 창고, 우물.
4. 산림: 목재, 사냥, 약초, 오두막.
5. 산업: 공장, 정비소, 창고, 발전 시설.
6. 군사: 검문소, 기지, 연구 자료.
7. 의료: 병원, 약국, 연구 시설.
8. 수변: 강, 호수, 낚시, 정수 설비.

각 구역은 시각 테마뿐 아니라 스폰 테이블, 루팅 테이블, 좀비 밀도, 자원 희소성, 외부 세력 점유를 가진다.

## 3. 스트리밍 구조

### 3.1 공간 단위

- 월드 좌표는 월드 원점 기준으로 저장한다.
- 내부 스트리밍 후보 크기: 256m 또는 512m 셀. 최종 크기는 테스트로 결정.
- **F-33(2026-11-23) 갱신:** 기본 월드를 4km × 4km로 키우면서 셀은 50m 그대로 뒀다(80 × 80칸). 생성 맵의 블록 하나가 셀 하나이고, 셀마다 미리 잡는 메모리가 없어서 칸 수는 비용이 아니다. 근거와 측정은 docs/09 §15.3.1, docs/15 §23.
- 활성 셀, 사전 로딩 셀, 비활성 셀의 세 가지 상태를 사용한다.
- 플레이어 이동 방향과 속도를 사용해 앞쪽 구역을 사전 로딩한다.

구현 메모(P3-1, 임시. docs/00 ADR-023, docs/09 §15.1): 셀 `(cx, cz)`는 `[cx·크기, (cx+1)·크기)`를 덮고 ID는 `cell_<cx>_<cz>`다(음수 좌표는 내림: x = -0.001은 셀 -1). 맵 경계 위나 밖의 위치는 가장자리 셀에 속한다. 500m × 500m 테스트 맵의 셀 크기는 50m, 활성 반경 2칸, 사전 로딩 반경 3칸이다(설정 `data/tuning/world_cell_settings.tres`). 256m·512m 후보 중 무엇을 4km 월드에 쓸지는 여전히 미결정이다. 사전 로딩은 서버가 가진 위치의 변화로 구한 속도로 4초 뒤 위치를 내다보며, 한 셀 너머까지만 본다.

### 3.2 셀 라이프사이클

`UNLOADED → LOADING → ACTIVE → SAVING → UNLOADING`.

- ACTIVE: 플레이어 주변 실시간 물리/AI/시각 처리.
- 비활성: 정적 지형/건물은 캐시 또는 해제. 영속 상태는 저장 데이터에 보관.
- unload 전에 엔티티 상태 및 이벤트를 저장한다.
- 로딩 실패 시 해당 셀을 활성화하지 않고 재시도/오류를 기록한다.

구현 메모(P3-2, 임시. docs/09 §15.2): 서버가 셀을 메모리에 두는 범위(위 사전 로딩 반경)와 별개로, **각 클라이언트가 내용을 받는 범위**가 있다: 자기 플레이어 셀에서 2칸 이내, 한번 받기 시작한 셀은 3칸까지 유지(설정 `data/tuning/interest_settings.tres`, 사전 로딩 반경을 넘지 못한다). 클라이언트는 셀 크기와 맵 경계를 접속할 때 서버에서 받아 500m × 500m 테스트 맵의 바닥과 가장자리 벽을 그리고, HUD에 지금 서 있는 셀 ID를 표시한다. 시험용으로 F3 키가 주변 셀의 경계선과 셀 ID를 켜고 끈다(docs/11 §2.15). 지형·건물은 아직 없다(평평한 바닥).

구현 메모(P3-1, 임시): 구현의 상태는 여섯이다. 위 경로의 LOADING과 ACTIVE 사이, ACTIVE와 SAVING 사이에 §3.1의 사전 로딩 셀에 해당하는 `PRELOADED`(메모리에 있지만 시뮬레이션하지 않음)가 있다: `UNLOADED → LOADING → PRELOADED ⇄ ACTIVE`, `PRELOADED → SAVING → UNLOADING → UNLOADED`. 로딩이 실패하면 `LOADING → UNLOADED`, 저장이 실패하면 `SAVING → PRELOADED`(저장되지 않은 것은 내리지 않는다)이고 둘 다 5초 뒤에 다시 시도한다. 지금은 좀비만 시뮬레이션 대상이다: ACTIVE가 아닌 셀의 좀비는 그대로 멈추고 원거리 요약 시뮬레이션(§3.3)은 아직 없다. 로딩·저장·해제는 동기 처리다.

### 3.3 원거리 시뮬레이션

원거리 NPC/가축/작물/부패는 실시간 프레임 단위가 아니라 시간 경과 기반으로 갱신한다. 중요한 사건(사망, 감염, 이주, 결혼, 범죄)은 별도 Event 레코드로 남긴다.

## 4. 월드 시간

- 월드 시간은 서버가 관리한다.
- 낮/밤, 시간 배율은 설정 데이터로 관리한다.
- 기본 협동 서버는 마지막 플레이어 퇴장 시 일시정지를 제안한다.
- 지속 서버는 오프라인 진행을 켤 수 있으나 오프라인 동안 처리할 시스템 목록과 계산 상한을 명시해야 한다.
- 게임 시간과 실제 시간의 변환은 `WorldClock` 단일 서비스가 담당한다.

## 5. 날씨와 계절

초기 기능: 맑음, 흐림, 비, 폭우, 안개, 눈, 폭풍. 계절은 온도/작물 성장/수자원/이동 난이도에 영향.

날씨 상태는 서버가 결정하고 클라이언트는 동일한 환경 상태를 표현한다. 날씨 이벤트는 시드와 시간으로 재현 가능해야 한다.

## 6. 자원/루팅 분포

- 건물 유형별 루팅 테이블.
- 지역 위험도와 건물 상태에 따른 수량 조정.
- 중요한 자원은 서버 측 스폰 시드로 결정.
- 셀 재활성화/재접속 시 루팅이 초기화되어 무한 파밍되는 문제를 방지한다.
- 재생성은 시간, 지역 설정, 서버 규칙에 따라 명시적으로 처리한다.

**구현 현황(P3-3, 임시, docs/00 ADR-026, docs/09 §15.3):** 건물 유형별 루팅 테이블은 데이터(`resources/definitions/loot_tables/`)이고 테스트 맵 건물(집·가게·진료소·창고)마다 테이블을 고른다. 보관함은 처음 수색될 때 "만들 때 기록한 월드 루팅 시드 + 보관함 ID"로 내용물이 한 번 정해지고, 수색 여부가 셀 문서에 저장되므로 셀 재활성화·재접속·서버 재시작으로 다시 생기지 않는다. 비운 보관함은 비어 있다. **재생성은 아직 없다**(규칙 미정, docs/15 P3-065). 지역 위험도·건물 상태에 따른 수량 조정은 아직 없다.

## 7. 월드 이벤트

화재, 정전, 도로 차단, 좀비 군집 이동, 외부 집단 이동/습격, 구조 신호 등. 이벤트는 원인, 위치, 시작/종료, 영향 엔티티, 결과를 저장한다.

## 8. 성능/품질 목표

아직 목표 하드웨어가 확정되지 않았으므로 프레임/메모리 절대 수치를 고정하지 않는다. 대신 초기 프로파일링에서 다음을 측정한다.
- 셀 로딩/해제 시간.
- 활성 셀/오브젝트 수.
- 내비게이션 갱신 시간.
- 서버 AI tick 시간.
- 클라이언트 프레임 시간.
- 저장/복구 시간.
- 네트워크 송수신량.

## 9. 수용 기준

- 셀 경계를 넘을 때 로딩 화면 없이 이동할 수 있다.
- 셀 unload/load 후 NPC, 아이템, 건축, 작물 상태가 유지된다.
- 서버에 접속한 모든 플레이어가 동일한 월드 시간/날씨를 경험한다.
- 원거리 시뮬레이션으로 인한 주요 사건이 기록된다.
