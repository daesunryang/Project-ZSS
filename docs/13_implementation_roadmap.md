# 13. 구현 로드맵 및 백로그

## 1. 진행 방식

각 Phase는 완성된 작은 수직 슬라이스를 만든다. 다음 Phase로 넘어가기 전에 현재 기능의 테스트/저장/네트워크 기준을 통과한다. 일정과 작업량은 팀 규모가 정해지지 않아 제시하지 않는다.

## 2. Phase 0 — 프로젝트 부트스트랩

- Godot 4.7.2 프로젝트 생성.
- 저장소/폴더 구조/코딩 규칙 적용.
- 클라이언트/헤드리스 서버 실행 설정.
- 자동 테스트 실행 경로 마련.
- 기본 로깅/설정/버전 정보.

완료: 빈 월드가 클라이언트와 headless server에서 실행되고 CI 또는 로컬 테스트를 통과한다.

## 3. Phase 1 — 네트워크와 플레이어 수직 슬라이스

- 서버 시작/클라이언트 접속.
- 플레이어 스폰/이동/카메라.
- 서버 권한 위치 처리.
- 인벤토리 기초.
- 플레이어 상태 저장/복구.

완료: 2개 클라이언트가 접속해 이동하고 아이템 하나를 공유 월드에서 획득/저장/복구한다.

## 4. Phase 2 — 생존/좀비/전투

- 허기/갈증/피로/건강.
- 기본 근접 무기.
- 좀비 감지/추격/공격.
- 소음 이벤트.
- 부상/감염 기초.

완료: 두 클라이언트가 동일 좀비와 전투하고 동일 결과를 확인한다.

## 5. Phase 3 — 월드 구역과 건축

- 500m × 500m 테스트 맵.
- 셀 로딩/해제.
- 건물 수색/루팅.
- 격자형 바닥/벽/문.
- 건축 청사진/자재/완공.
- 내비게이션 갱신.

완료: 셀 이동/저장/복구가 되고 두 플레이어가 같은 구조물을 본다.

## 6. Phase 4 — NPC AI 기반

- NPC 데이터와 고유 ID.
- 성격/능력/욕구.
- 욕구 충족 행동.
- 기본 업무/이동/휴식.
- 감정/기억/관계의 데이터 구조.
- AI 디버그 오버레이.

완료: NPC 5명이 자율적으로 기본 생존/업무를 하고 저장 후 복구된다.

## 7. Phase 5 — 사회/관계/사건

- NPC 간 대화/도움/갈등.
- 관계 축과 비대칭 상태.
- 기억/사건 원장.
- 연애/결혼 기본 흐름.
- 소문/목격/증거 기초.
- 절도/탈주 등 초기 범죄.

완료: 플레이어가 보지 않는 NPC-NPC 사건이 발생하고 기록/조사할 수 있다.

## 8. Phase 6 — 농업/가축/쉘터 운영

- 농장/작물 2~5종.
- 가축 닭/소 우선.
- 축사/먹이/물/건강/생산.
- NPC 농업/동물 돌봄 업무.
- 식품 가공/보관/부패.
- 쉘터 식량/물/전력 요약.

완료: 작은 쉘터가 농업과 가축으로 일부 자급자족한다.

## 9. Phase 7 — 세계 확장

- 월드 후보 크기 확장.
- 차량.
- 외부 생존 세력.
- 백신 연구/치료.
- 날씨/계절.
- 동물 감염.
- 더 복잡한 사건/정책.

## 10. Phase 8 — 성능/콘텐츠 완성

- AI/네트워크/월드 최적화.
- 장시간 서버 테스트.
- UI/아트/오디오 확장.
- 난이도/월드 생성/루팅 밸런스.
- 서버 관리와 배포.

## 11. 권장 최초 수직 슬라이스

- 플레이어 2명.
- NPC 5명.
- 좀비 10~20마리.
- 건물 5~10개.
- 구조물 10종.
- 농장 1개, 닭 3마리, 소 1마리.
- 작물 2~5종.

이 수량은 성능 보장이 아니라 최소 기능을 검증할 초기 테스트 규모다.

## 12. 작업 티켓 순서

1. 프로젝트 부트스트랩 및 export preset.
2. 서버 권한 세션/접속.
3. 플레이어 이동/카메라/동기화.
4. 엔티티 ID/인벤토리 트랜잭션.
5. 저장/복구.
6. 월드 셀 manager.
7. 좀비 AI와 소음.
8. 생존 상태/감염.
9. 건축 MVP.
10. NPC 도메인 모델/AI scheduler.
11. 관계/이벤트.
12. 농업/가축.

## 13. Claude Code 실행 규칙

각 티켓은 한 번의 작업에서 한 개의 핵심 완료 목표를 갖는다. 변경 파일, 위험, 테스트를 먼저 계획한다. 문서와 충돌하면 구현보다 문서 불일치 보고를 우선한다.

## 14. Phase 2 티켓 현황 (2026-11-15 갱신)

Phase 2는 단일 조정자(Opus)가 티켓을 쪼개고 병합한다. 설계 난도가 높은 작업(AI, 전투·네트워크 동기화)은 Fable 에이전트, 독립적인 생존 로직은 Codex, 검토·병합·검증은 조정자가 맡는다. 모든 티켓은 `tools/check.sh` 통과 후 main 에 병합한다. 상세 가정은 `docs/15` §6.
