# F-29 생존 우선 결정과 수색 (브랜치 `f29-scavenge`)

기준 main `89e1ec8`. 계약은 docs/09 §17.14, 임시 가정과 측정은 docs/15 §25(F29-001~F29-016).

## 사용자 지시 원문 (2026-11-23)

> 그렇게 고치고 npc는 랜덤 집에서 혼자 버티고 살아남는 형태, 유저가 발견했을 때 포섭을 할 지 죽일지는 유저 선택, 역으로 성격이 포악하거나 대화에서 트러블이 생길 시 유저를 공격할 수 있음
> npc는 자유의지가 있으며 생존을 최우선 시 함
> 거처를 바꿔다닐 수도 있음

일하기에 대한 답(같은 날): "일 할수도 있고 자유롭게".

조정자 지시(요약): 범위는 F-29만(기존 F-15·F-16 흡수). 수색(자기 집 먼저, 그다음 반경 안의 생성 건물, 거리와 기억한 위험으로 고름, 보관함은 플레이어처럼 `search_now`, 쓸 것을 챙겨 집으로, 남는 것은 집 보관함에, 인벤토리 한도, 비운 건물 기억), 생존 우선 점수(도망·먹기·마시기·치료·잠·수색·자유 활동, `work`는 혼자 사는 NPC에게 여전히 안 씀), 위협 기억과 피하기(기억 구성 요소), 몰리면 싸움(기존 근접 규칙, 플레이어는 공격하지 않음: F-32), 저장·재시작·셀 내리기에서 그대로, 먼 NPC는 기존 규칙(멈춤) 유지하고 적어 둘 것, 테스트·측정, 문서는 한국어.

## 2026-11-24에 정한 것

사용자가 정한 것은 위 인용뿐이고, 아래는 전부 이 작업에서 임시로 정했다.

- **F-29 전체를 설정 하나로 켜고 끈다.** `CompositionConfig.npc_scavenge`(기본 켜짐). null이면 NPC는 F-28까지의 모습 그대로다. F-25의 체력 테스트와 F-28의 "집에서 사는 하루" 테스트 둘은 이것을 끄고 돈다(아래 "기존 테스트").
- **조회 창구 하나.** 결정 계층과 행동 계층이 같은 것을 물어야 해서(모자란 정도, 치료할 수 있는지, 위험) `NpcSurvivalSense`를 뒀다. 자기 상태가 없다: 재고는 인벤토리에서 세고, 위험은 기억 구성 요소에서 읽는다.
- **새 행동은 난수를 뽑지 않는다.** 결정 한 번에 "행동 하나당 난수 하나"를 뽑는 규칙 때문에, 행동을 그냥 더하면 기존 월드와 기존 테스트의 NPC가 뽑는 난수 순서가 전부 바뀐다. `draws_jitter = false`로 새 셋을 뺐다. 그래서 개발 맵 구성의 기존 테스트(수용 3일, 하루 실행, 밤잠, 측정)가 한 줄도 고치지 않고 통과한다.
- **"모자란 정도"를 욕구 항에 넣었다.** 점수 식에 새 항을 만들지 않고, 행동 정의에 "욕구 항이 보급 부족"이라는 표시(`need_is_supply_shortage`)를 뒀다. 점수 기록·디버그 오버레이가 그대로 읽는다.
- **수색은 끝까지 가는 행동.** 처음에는 매 결정마다 다시 겨뤘는데, 음식을 집어 드는 순간 부족이 줄어 도중에 그만둘 수 있었다. 잠과 같은 "끝까지"(`runs_until_done`)로 바꾸고, 그것을 끊는 조건에 "지금 치료할 수 있다"를 더했다(붕대를 찾자마자 감는다).
- **원하는 만큼만 가져온다.** 처음 만든 판은 하루에 음식 38단위를 집으로 쓸어 왔다(F-28 하루 테스트에서 15 → 53). 음식·음료는 원하는 양까지만 꺼내고 남은 건물은 `left`로 기억하게 바꿨다(F29-003, **[사용자 확인 필요]**).
- **수색 범위 55m.** 길찾기 반경(60m)이 상한이다. 설정 검사가 막는다(F29-002).
- **건물 고르기는 캐시 상태와 무관하다.** 셀의 건물 목록을 생성기 계획에서 만들어 캐시하는데, 처음 고를 때 셀 12개를 한 틱에 계획하면 2~3ms가 걸렸다. "틱당 몇 개만"으로 나누면 재시작한 서버(빈 캐시)와 계속 돈 서버가 다른 건물을 고르게 된다. 그래서 고를 때는 빠진 셀을 전부 계획하고, 대신 NPC가 깨어날 때 집 주변 셀을 줄 세워 틱당 하나씩 미리 계획한다. 고르기 최악이 2.9ms → 0.4ms가 됐다.
- **진행 중인 건물 id를 집으로 돌아오는 길에도 유지한다.** 처음에는 돌아올 때 집 id로 바꿨는데, 그러면 저장 문서만 봐서는 어느 건물을 다녀오는 길인지 알 수 없다.
- **위험 기억은 기억 구성 요소를 그대로 쓴다**(지시대로). 같은 사건 id로 합치려면 자리와 시각이 같아야 해서(`_merge_existing`), "가까운 곳에 최근 것이 있으면 새로 만들지 않는다"로 했다. 추격당하면 10m마다 하나씩 남는다(상한 64개, 약한 것부터 밀려남).
- **위험 기억은 모든 NPC에게 생긴다**(개발 맵의 집에 사는 NPC도). 쓰는 곳은 수색뿐이다. 기존 테스트 중 좀비를 보는 NPC가 있는 것들은 그대로 통과했다.
- **자가 치료를 행동으로 옮겼다**(F25-004가 미뤄 둔 것). 체력 단계의 자동 규칙은 코드에 남기고, 결정 계층에 `treat`가 있는 구성에서만 끈다(`NpcHealth.self_treat_by_action`).
- **싸움의 대상은 저장하지 않는다.** 공격할 때마다 닿는 거리 안의 가장 가까운 좀비를 고른다. 구성 요소 스키마를 건드리지 않아도 되고, 지목한 좀비가 죽고 다른 좀비가 붙어 있는 경우도 맞게 된다.
- **닿는 거리를 1.6m로 늘렸다**(F29-008). 무기 사거리 그대로면 식칼(1.3m)을 든 NPC는 좀비(1.5m에서 멈춤)를 못 때린다.
- **NPC의 굴림은 NPC 난수에서.** 전투 시스템의 난수를 쓰면 NPC가 싸울 때마다 플레이어의 피해 굴림 순서가 달라진다.
- **화면 라벨·프로토콜은 그대로.** `PROTOCOL_VERSION` 변경 없음. 수색은 `walk`/`idle`, 싸움은 `flee`로 보인다(F29-010, **[사용자 확인 필요]**). 처음에는 수색에 `work` 라벨을 붙였다가 "혼자 사는 NPC는 일하지 않는다"(F-28)와 겹쳐서 뺐다.
- **ADR은 쓰지 않았다.** docs/00은 조정자가 병합 때 넣을지 정한다(내용: "혼자 사는 NPC는 수색으로 살고, 생존 규칙은 `npc_scavenge` 하나로 켜고 끈다. 새 행동은 난수를 뽑지 않는다").
- **소유 영역 밖 변경**: `npc_homes.gd`(건물 한가운데·보관함 자리 조회 둘), `npc_service.gd`(`is_seeded_home`), `npc_health.gd`(`self_treat_by_action`), `npc_behaviour_state.gd`(`capacity`), `composition_config.gd`·`server_composition.gd`(조립), `tests/framework/npc_life_run.gd`(생존 계층을 끄는 선택 인자), `tests/test_tiers.cfg`·`tests/test_changes.cfg`. 좀비·전투·보관함·생성 맵·네트워크 코드는 고치지 않았다. docs/09는 파일 끝(§17.14), docs/15는 파일 끝(§25), docs/13은 D2·D3에 한 줄씩.

## 기존 테스트를 고친 곳 (뜻이 바뀐 것만)

- `npc_decision_test.gd`: "배포된 행동은 일곱 개" → 열 개(이름 나열), "끝까지 가는 행동은 낮잠·밤잠뿐" → 수색 포함. 새 단언 둘(싸움은 선택 불가, 새 행동은 난수를 안 뽑음).
