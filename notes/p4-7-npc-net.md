# P4-7 NPC 복제 작업 메모

## 2026-11-19 사용자 지시

> "지금부터 쭉 작업을 진행하고 마지막에 수치랑 규칙 조정을 하자"

> "필요한 작업있으면 codex 사용량을 좀 더 늘려서 활용해"

P4-7 범위는 docs/13 §16.1 행 그대로 구현한다. `scripts/domain/npc/`는 P4-1 소유라 수정하지 않는다. 커밋·reset·rebase·checkout·stash는 쓰지 않고 조정자가 검토·검사 뒤 커밋한다.

## 2026-11-19 정한 것

- 전선 공개 행은 NPC ID·표시 이름·외형 선택지·위치·방향·관찰 가능한 행동 라벨·자세 일곱 값의 화이트리스트다. `definition_id`, 구성 요소, 욕구, 감정, 기억, 관계, 성격, 능력, 목표, RNG는 보내지 않는다.
- 접속·`npc_entered`는 전체 공개 행, 5Hz ch2 스냅샷은 ID·위치·방향만 보낸다. 행동 라벨 변화는 ch0 `npc_action_changed`다. 관심 셀 대조는 스냅샷 틱에만 한다.
- 행동 라벨 목록은 `idle`, `walk`, `eat`, `sleep`, `work`, `flee`; P4-7 기본은 `idle`. P4-4가 `(NpcState) -> String` 읽기 함수 하나를 주입한다.
- NPC 자세 모델은 아직 없으므로 P4-7은 `standing`만 보낸다. 미러는 앞으로 쓸 플레이어 자세 이름 셋을 검증한다.
- 캡슐은 한 MultiMesh로 묶고 한국어/표시 이름표만 NPC별 Label3D로 둔다. 임시 수치는 docs/15 P4-121~130에 적었다.
- `PROTOCOL_VERSION`은 16이다. 다른 병렬 티켓과 합칠 때 조정자가 최종 번호를 다시 정한다.

## 2026-11-19 테스트 기록

- 테스트를 먼저 추가하고 `tools/run_tests.sh --filter=npc_net`을 실행했다. 구현 전에는 새 클래스가 없어 **0 통과, 2 로드 실패**를 실제로 확인했다.
- 핵심·표시 구현 뒤 같은 필터의 테스트 본문은 **10 통과, 0 실패**다(통합 2, 단위 8). 두 클라이언트 동일 행, `set_npc_transform`, 관심 밖 `npc_left`, 행동 라벨 이벤트, 실제 접속 조각의 비공개 표식 부재, RPC 채널, 미러 검증, MultiMesh·한국어 이름표를 포함한다.
- 현재 샌드박스에서는 Godot이 `user://logs`와 Windows 인증서 저장소를 열지 못해 테스트 본문 통과 뒤에도 래퍼 종료 코드는 1이다. 전체 `tools/check.sh`, 실제 창 캡처와 전용 서버 별도 프로세스는 조정자가 밖에서 다시 확인한다.
