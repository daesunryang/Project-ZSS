# F-3 근접 무기 다양화 — 작업 중 정한 것

브랜치 `f3-melee`, 2026-11-23. 수치·임시 가정의 전체 표는 `docs/15_risks_and_open_questions.md` §20(F3-01~F3-07).

## 사용자 결정 (원문)

- FD-3: "60~200회로 하되 재료 구하면 수리 가능 / 수리 레벨 높으면 재료 감소" — 이 티켓은 60~200회와 부서짐까지. 수리는 F-10.
- 무기: "맨손은 10대, 무기 다양화 예정, 총기, 근접무기" — 맨손 수치는 그대로 둔다.

## 2026-11-23에 정한 것

- 내구도는 새 저장 필드를 만들지 않고 기존 `ItemInstance.condition`(0~1)에 "남은 횟수/최대 횟수"로 넣었다. 이미 저장·복제·보관함 이동에 따라다니는 값이라 저장 형식과 네트워크 메시지가 바뀌지 않는다. 남은 횟수는 반올림으로 되읽어 JSON 소수 오차(AGENTS.md §12)에 걸리지 않는다.
- 맞힌 공격만 닳는다. 같은 무기 둘이면 슬롯 번호가 작은 것부터.
- 부서진 무기는 사라진다(부서진 아이템을 남기지 않음). F-10에서 바꿀 수 있다.
- 닳음마다 저장하지 않는다(다음 정기 저장). 부서짐은 기존 `item_removed` 경로라 그 틱에 저장된다.
- 루팅: F-1과 같은 표 줄을 고치지 않으려고 하위 표(`subtable_ids`/`subtable_weights`)를 더했다. 무기는 `melee_household`·`melee_store`·`melee_tools` 세 파일에만 있고, 기존 건물 표에는 `script =` 바로 아래 두 줄만 더했다. 하위 표가 없는 표는 전과 똑같이 굴린다.
- 희귀도는 무기 정의의 `rarity`, 무기 표의 가중치는 희귀도에서 나온다(테스트가 맞는지 본다). 제작 전용 셋(창·못 박힌 방망이·가시 철사 방망이)은 어느 루팅 표에도 없다.
- 전기톱 연료는 연료 아이템이 없어 넣지 않았다(소음 40만 다름). 전기충격봉 기절 같은 특수 효과도 없다.
- `PROTOCOL_VERSION`은 그대로(새 메시지·새 공개 필드 없음).
