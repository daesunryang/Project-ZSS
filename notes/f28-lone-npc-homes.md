# F-28 혼자 사는 NPC의 집 (브랜치 `f28-lone-homes`)

기준 main `2e1aa2f`. 계약은 docs/09 §17.13, 임시 가정과 측정은 docs/15 §24(F28-001~F28-012).

## 사용자 지시 원문 (2026-11-23)

> 그렇게 고치고 npc는 랜덤 집에서 혼자 버티고 살아남는 형태, 유저가 발견했을 때 포섭을 할 지 죽일지는 유저 선택, 역으로 성격이 포악하거나 대화에서 트러블이 생길 시 유저를 공격할 수 있음
> npc는 자유의지가 있으며 생존을 최우선 시 함
> 거처를 바꿔다닐 수도 있음

조정자의 물음에 대한 답(같은 날, notes/npc-lone-survivor-plan-2026-11-23.md):

- 건물 수: "맵에 크기를 광활하게 해야해 집이 엄청 많아야해 프로젝트 좀보이드 처럼" (F-33으로 끝남)
- 포섭한 NPC: "포섭에서 같이 살고 플레이어가 동행요청하면 같이 돌아다니고" (F-32)
- 죽은 NPC가 좀비가 되는지: "그렇게 해" (F-25로 끝남)
- 일하기: "일 할수도 있고 자유롭게"

조정자 지시(요약): 범위는 F-28만. 명단 NPC마다 월드 시드로 고른 생성 건물 하나(집 먼저, 한 건물에 한 명, 마을과 시골에 흩어서), 저장에 기록, 재시작해도 같게. 자리(침대·물·음식)는 생성 건물의 배치에서 계산. 음식은 그 건물 보관함의 것(공짜로 채우지 않음, 루팅에 음식이 없으면 작은 임시 식량을 정하고 표시). 일터 출근 없앰(`work` 행동은 남김). 이전 월드는 정해서 문서에(한 번 옮기기를 권함). 테스트는 뜻을 지키고, 측정하고, 문서는 한국어.

## 2026-11-24에 정한 것

사용자가 정한 것은 위 인용뿐이고, 아래는 전부 이 작업에서 임시로 정했다.

- **"혼자 사는 배치"는 생성 맵이 있는 월드에서만.** 조건을 따로 만들지 않고 "생성 맵이 있나"로 갈랐다(끄는 설정 `lone_homes`도 있다). 테스트는 거의 전부 생성 맵 없이 돌기 때문에, NPC 행동 일반을 보는 기존 테스트(수용 3일, 하루 실행, 밤잠, 셀 저장, 측정)는 개발 맵의 집·자리·일터·식량이라는 통제된 구성을 그대로 쓴다. 그 테스트들의 단언은 하나도 고치지 않았다. 새 규칙은 새 테스트 파일(`npc_lone_home_test.gd`)이 본다.
- **집은 NPC의 저장되는 상태다.** 정의(`NpcDefinition.home_building_id`)는 "개발 맵에서의 집"으로 남기고, 구성 요소 `home`을 새로 뒀다. F-30(이사)이 이 구성 요소만 바꾸면 된다. 구성 요소가 없는 옛 문서는 "정의의 집"으로 읽는다.
- **자리는 저장하지 않고 건물에서 계산한다.** 자리 id에 건물 id를 넣어서(`gen_n12_p3_0_bed`), 실행 계층이 id만으로 생성기에게 물어 위치를 찾는다. 건물 수천 채의 자리 목록을 만들지 않는다. 생성기 계획은 셀을 올리지 않고 0.1ms쯤에 나온다.
- **생성 집에 사는 NPC는 자기 건물의 자리만 쓴다.** 처음에는 기존 "가까운 자리 아무거나"를 그대로 두려 했지만, 그러면 물이 없는 NPC가 2km 떨어진 개발 맵 우물을 고르고 길찾기 실패를 되풀이한다.
- **일터를 없애는 방법**: `work` 행동과 근무 시간대 정의는 건드리지 않고, "일터가 있는가"를 정의가 아니라 `home` 구성 요소에 물었다. 생성 집에 사는 NPC는 일터가 없다. 결정 계층은 이미 있던 `no_job` 거절을 쓴다.
- **보관함 루팅은 플레이어가 처음 열 때 굴린다**는 것을 작업 중에 알았다(F33-010). 그대로면 NPC가 보는 보관함은 늘 비어 있다. 그래서 NPC를 집에 넣을 때 그 건물 보관함을 수색한 것으로 만든다(`ContainerService.search_now`, 플레이어가 열 때와 같은 시드).
- **집 식량 6단위.** 루팅만 재 보니 집 한 채에 음식 1~13단위였고 음식이 없는 건물 종류도 있다. 조정자 지시대로 작은 임시 식량을 정했다: 전투식량 6단위(약 3일치), 집에 넣을 때 한 번. **[사용자 확인 필요]**(docs/15 F28-005).
- **집 셀을 끝까지 짓고 나서 NPC를 놓는다.** 생성 맵은 원래 플레이어가 가까이 올 때 조금씩 짓는다. NPC가 벽이 없는 자리에 서 있다가 벽이 생기면 조각이 빠진다("누가 서 있는 변"). 그래서 `finish_cell_now`를 더했다.
- **이전 월드: 한 번 옮긴다.** NPC가 어느 셀에 있는지는 월드 문서에 없어서(셀 문서에만 있다) 시작할 때 찾아다니지 않고, NPC가 메모리에 들어올 때 옮긴다. 틱마다 한 명. "옮겼다"는 기록은 NPC의 `home` 구성 요소 자체다. 하던 행동은 취소하지 않았다(실행 계층이 다음 걸음에서 스스로 실패한다). **[사용자 확인 필요]**(docs/15 F28-010).
- **프로토콜·스키마 번호는 그대로.** NPC 문서에 구성 요소 하나, 명단 기록에 `homes` 키 하나가 늘었고 둘 다 없는 저장을 읽는다.
- **ADR은 쓰지 않았다.** docs/00은 조정자가 병합 때 넣을지 정한다(내용: "명단 NPC는 생성 건물에 혼자 살고, 집은 NPC의 저장 상태이며, 자리는 건물에서 계산한다").
- **소유 영역 밖 변경**: `procedural_map_generator.gd`(id 되읽기·건물 찾기·셀 크기: 배치는 안 바뀜), `procedural_map_service.gd`(`finish_cell_now`), `container_service.gd`(`search_now`, `container_id_of_source`), `composition_config.gd`·`server_composition.gd`·`game_bootstrap.gd`(조립·주석), `tests/framework/npc_life_run.gd`(생성 맵을 받는 선택 인자), `tests/test_tiers.cfg`·`tests/test_changes.cfg`(각 한두 줄). docs/09는 파일 끝(§17.13), docs/15는 파일 끝(§24).

## 측정

docs/15 §24.1 표가 기준이다. 요약(2026-11-24, 같은 PC에서 다른 작업이 돌았을 수 있음): 집 10채 고르기 6.4~7.0ms, 새 월드의 명단 배치 280~291ms(개발 맵의 집일 때 98ms), 이전 월드의 NPC 한 명 옮기기 최대 15ms, NPC가 모두 먼 집에 있을 때 NPC 단계 0.007ms/틱, 한 명이 깨어 있을 때 월드 틱 0.31ms.

기존 측정(`npc_measure_test.gd`, 25명)은 main과 같다(단계 중앙값 0.296ms). 다만 "25명의 NPC 문서 만들기 ≤ 2ms"는 main에서 이미 2.25~2.30ms로 넘고 있고(경고), 이 브랜치는 2.26~2.38ms다. NPC 단계 최악도 한도 2.0ms에 붙어 있어 다른 테스트와 같이 돌 때 2.1ms 경고가 난다. 한도는 건드리지 않았다.

## 확인하지 못한 것

docs/15 §24.2. 요약: 실제 게임 창에서 본 적 없음, 생성 좀비를 켠 마을에서 NPC가 얼마나 버티는지, 여러 날 실행, 2 peer 시나리오, 실제 프로세스로 옛 저장 올리기.

## 사용자가 정할 것

1. NPC를 어디에 흩을지(F28-003): 지금은 마을마다 한 명 + 10명 중 3명은 시골. 시작점 가까이에 몇 명 둘지.
2. 처음 가진 식량(F28-005): 지금은 전투식량 6단위 한 번.
3. 물(F28-006): 지금은 집마다 마르지 않는 물 자리.
4. 이전 월드의 NPC(F28-010): 지금은 한 번 새 집으로 옮김.
5. 혼자 살 때의 일(F28-009): 지금은 일하지 않음("할 수도 있고"는 F-19).
