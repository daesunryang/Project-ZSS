# 저장 정밀도 작업 기록

브랜치 `fix-save-precision`. 저장 파일과 셀 해제 복사를 full precision JSON으로 쓰는 `a7004f5` 위에서 NPC 욕구 구성 요소 자체의 손실 없는 저장 형식을 다룬다.

## 2026-11-19

사용자 지시(원문):

> "지금부터 쭉 작업을 진행하고 마지막에 수치랑 규칙 조정을 하자"

이번 작업에서 정한 것:

- `NpcNeeds` schema 2는 저장되는 모든 float를 IEEE-754 64비트 8바이트의 base64 문자열로 쓴다. 욕구 값/달력 초/초당 비율이라는 계산 단위와 연산 순서는 바꾸지 않는다.
- 비율만 하루 단위처럼 키우면 0.1 미만의 현재값·구간 시작값·시각·modifier가 같은 JSON 파서 손실에 남는다. 전체 float의 비트를 저장해 값 범위와 수치 튜닝에 관계없이 셀 해제와 파일 저장을 같은 방식으로 보존한다.
- schema 1의 숫자 문서는 읽기 호환한다. 이미 JSON 파서에서 잃은 끝 비트는 복원할 수 없지만, 로딩한 값과 옛 구간 비율을 이어 가고 다음 저장부터 schema 2로 쓴다.
- `schedule`과 `decision`은 저장 시각을 정수 µs로 보관한다. 현재 `NpcActionExecutor`는 P4-4 인터페이스뿐이고 별도 저장 구성 요소 문서가 없다.
