# 그림 루프 (art-loop)

자세한 설명은 `docs/19_art_loop.md`, 정해진 것의 기록은 `notes/art-loop.md` 에 있습니다. 먼저 둘을 읽습니다.

## 반드시 지킬 것

- **이 루프는 그림을 승인하지 않습니다.** 수치가 깨끗하고 점수가 5점이어도 "통과"·"승인"·"완료"라고 말하거나 적지 않습니다. 멈추면 사용자에게 보여 주고 묻습니다.
- 사용자의 가장 최근 지시가 이 문서보다 앞섭니다.
- 사용자가 손으로 고친 파일(기준표, 기준 그림, 설정, 그림 파일)을 덮어쓰지 않습니다.
- `art/loop/rubric.md` 의 `[빈칸 — 사용자 작성]` 과 `art/loop/reference/` 는 사용자만 채웁니다. 비어 있으면 지어내지 말고 사용자에게 묻습니다.
- 새로 정해진 것은 날짜와 함께 `notes/art-loop.md` 에 적습니다. 사용자가 한 말은 그대로 옮깁니다.
- 지난 회차 폴더(`art/loop/runs/<작업>/rNN/`)는 기록입니다. 고치거나 지우지 않습니다.

## 시작

```bash
tools/art_loop.sh start <작업이름> "<사용자가 말한 목표 그대로>"
```

작업이름은 영문 소문자·숫자·`-`·`_`. 목표는 사용자의 말을 고치지 않고 넣습니다.
`NOT READY FOR REVIEWERS` 가 나오면 기준 그림이나 기준표 빈칸이 비어 있는 것입니다.
이때는 1회차의 스냅샷과 수치까지만 만들 수 있고 채점은 못 합니다. 사용자에게 무엇이 필요한지 알리고 기다립니다.

## 한 회차

1. **그림 만들기·고치기** — `.claude/skills/codex-art-handoff/SKILL.md` 대로 Codex 에 넘깁니다(먼저 읽을 것 / 사용자 말 그대로의 목표 / 손댈 수 있는 범위 / 금지). 2회차부터는 지난 회차의 수치와 검토자가 쓴 이유를 지시문에 넣어도 됩니다. Codex 가 통과·실패·실행 못 함으로 보고하면, 파일·검사·렌더를 직접 다시 확인합니다.
2. **스냅샷** — 결과를 PNG 로 남깁니다. 게임 안 모습이면 `tools/capture_view.gd`(머리말에 사용법)로 게임 창을 찍고, 그림 파일 자체면 그 파일을 씁니다. 회차끼리 견줄 수 있게 **매 회차 같은 이름·같은 크기·같은 구도**로 찍습니다.
3. **기록과 측정**
   ```bash
   tools/art_loop.sh round <작업이름> <png> [<png>...]
   ```
   `rNN/snapshots/` 에 복사하고, `rNN/metrics.json` 을 쓰고, `scores.json` 에 회차를 더합니다.
   `status: stopped_show_user` (수치가 나빠짐)이면 채점하지 않고 "멈춤"으로 갑니다.
4. **검토자 묶음**
   ```bash
   tools/art_loop.sh pack <작업이름>
   ```
   프로젝트 밖 임시 폴더에 기준표·기준 그림·스냅샷(이름은 `snapshot_01.png` 처럼 바뀜)만 모으고, 검토자에게 줄 글을 그대로 출력합니다.
5. **검토자 둘** — Agent 도구로 **새 하위 에이전트 둘**을 한 메시지에서 같이 띄웁니다.
   - `fork` 는 쓰지 않습니다(지금까지의 대화를 물려받습니다). 매 회차 새로 띄우고, 지난 회차 검토자를 다시 부르지 않습니다.
   - 프롬프트는 4에서 출력된 글 **그대로**입니다. 작업 이름, 회차, 지난 점수, 수치, 만든 쪽의 설명, 바라는 점수를 한 글자도 덧붙이지 않습니다.
   - 두 검토자에게 같은 글을 줍니다. 서로의 답을 보여 주지 않습니다.
6. **답 저장** — 각 검토자의 JSON 을 고치지 않고 `rNN/reviews/reviewer_1.json`, `reviewer_2.json` 으로 저장합니다.
   모양이 틀리면 점수를 손으로 고치지 말고, 같은 글로 **새** 검토자를 띄워 그 답으로 바꿉니다.
7. **평균과 판단**
   ```bash
   tools/art_loop.sh record <작업이름>
   ```
   항목별 평균과 전체 평균을 `scores.json` 에 적고 다음 상태를 알려 줍니다.
   - `continue` → 다음 회차(1로).
   - `stopped_show_user` → "멈춤".

## 멈춤 — 사용자에게 보여 주기

멈추는 경우: 회차 상한(기본 5), 가장 높았던 점수보다 0.25 이상 오르지 못한 회차가 2번, 스크립트 수치가 나빠짐. (값은 `art/loop/settings.json`)

```bash
tools/art_loop.sh report <작업이름>
```

사용자에게 보여 줄 것:

1. 점수가 가장 높은 회차의 스냅샷(그림을 직접 보여 줍니다. 경로만 적지 않습니다).
2. 회차별 점수표와 수치 추이(report 가 낸 표).
3. 왜 멈췄는지 한 줄.
4. 검토자들이 쓴 이유 가운데 갈린 것.

그리고 묻습니다: 이 회차로 갈지, 더 돌릴지, 방향을 바꿀지. **판단은 사용자가 합니다.**

사용자가 더 돌리라고 하면 그 말을 그대로 넣어 다음 회차를 엽니다(말은 `job.json` 에 남습니다).

```bash
tools/art_loop.sh round <작업이름> --user-said-continue="<사용자 말 그대로>" <png> [<png>...]
```

## 하지 말 것

- 검토자에게 기준표·기준 그림·스냅샷 말고 다른 것을 주는 일.
- 검토자 답의 점수나 이유를 고치는 일, 평균을 손으로 적는 일.
- `settings.json` 의 문턱값을 점수가 잘 나오게 바꾸는 일(바꿀 까닭이 있으면 사용자에게 묻고 `notes/art-loop.md` 에 적습니다).
- 멈춘 루프를 사용자 말 없이 이어 가는 일.
- "승인됨", "통과" 같은 말을 파일이나 보고에 쓰는 일.
