# Codex 그림 작업 넘기기

사용자 지시(2026-11-17): "그림이 필요한 작업은 Codex한테 넘기는 스킬을 만들어 줘. 지시서엔 먼저 읽을 것, 목표(내 말 그대로), 고쳐도 되는 범위, 하면 안 되는 일을 쓰고, Codex는 통과·실패·못 돌림 중 하나로 보고하게 해. 결과는 네가 바뀐 파일·검사·렌더를 다시 확인한 뒤에만 커밋해."

규칙은 `AGENTS.md`를 따른다(특히 §0: 최신 지시 우선, 사용자가 고친 파일 덮어쓰지 않기, 자동 검사 통과는 미술 승인이 아님).

## 1. 준비

1. 작업용 worktree를 만든다: `git worktree add -b <브랜치> ../Project-ZSS-wt-<이름> main`.
2. 고칠 파일에 사용자가 직접 고친 흔적이 있는지 본다(`git log --format='%an %ae' -- <파일>`에 Claude가 아닌 작성자, 또는 커밋되지 않은 사용자 편집). 있으면 넘기지 말고 사용자에게 먼저 묻는다.
3. 그림 루프로 다듬을 작업이면 `.claude/skills/art-loop/`(그림 루프)의 회차 폴더를 먼저 만든다. 이 스킬은 한 회차의 "그림 만들기/고치기"를 맡는다.

## 2. 지시서 양식 (그대로 채운다)

지시서는 공유 노트 폴더나 스크래치 폴더에 `ticket_<이름>_codex.md`로 쓰고, 파일이 실제로 생긴 것을 확인한 뒤에만 Codex를 실행한다(`test -f`).

```markdown
# <작업 이름> (Codex)

작업 폴더: <worktree 경로>, 브랜치 <이름>, 기준 커밋 <해시>. 이 폴더 밖은 건드리지 않는다. 기록을 바꾸는 git 명령(commit, reset, rebase, checkout, stash)은 쓰지 않는다. 커밋은 조정자가 한다.

## 먼저 읽을 것
- AGENTS.md (특히 §0)
- <관련 docs 절, 기존 그림·씬·셰이더 파일, 기준 그림 폴더>

## 목표 (사용자 말 그대로)
"<사용자 말을 한 글자도 바꾸지 않고>"
<조정자가 덧붙이는 구체화가 있으면 '조정자 해석:'이라고 따로 표시>

## 고쳐도 되는 범위
- <파일·폴더 목록. 새 파일은 어디에 만드는지>

## 하면 안 되는 일
- 범위 밖 파일 수정, 게임 규칙·수치 변경, 사용자가 고친 파일 덮어쓰기
- 외부 이미지·모델을 내려받거나 출처를 알 수 없는 소재 사용
- 테스트를 약하게 만들기, 검사 결과를 지어내기
- <작업별로 더 금지할 것>

## 확인 방법
- 검사: `GODOT="C:/Users/박서준/Desktop/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe" bash tools/run_tests.sh --filter=<관련>`
- 렌더: `tools/capture_view.gd`로 게임 창 화면을 PNG로 남긴다(사용법은 그 파일 머리말). 샌드박스에서 창을 못 띄우면 못 돌린 것으로 보고한다.

## 보고 (한국어, 맨 첫 줄은 다음 셋 중 하나만)
- `결과: 통과` — 확인 방법을 모두 실제로 돌렸고 모두 통과했다
- `결과: 실패` — 돌렸는데 실패한 것이 있다(무엇이 왜)
- `결과: 못 돌림` — 하나라도 실제로 돌리지 못했다(무엇을 왜). 일부만 돌렸으면 이것이다
그 아래에: 바꾼 파일 목록, 실제로 본 검사 결과(개수), 남긴 렌더 파일 경로, 확인하지 못한 것.
```

## 3. 실행

```bash
export PATH="$PATH:/c/Users/박서준/AppData/Roaming/npm"
cd "<worktree>" && test -f "<지시서>" && codex exec --sandbox workspace-write -C . - < "<지시서>" > "<로그>" 2>&1
```

백그라운드로 돌리고 끝날 때까지 기다린다. 로그 끝의 보고에서 첫 줄이 셋 중 하나가 아니면 형식 위반으로 보고, 다시 보고하게 하거나 "못 돌림"으로 취급한다.

## 4. 조정자의 재확인 (이걸 다 하기 전에는 커밋하지 않는다)

1. **바뀐 파일**: `git status --short`와 `git diff --stat`으로 범위 밖 파일이 바뀌지 않았는지 본다. 범위 밖 변경이 있으면 되돌리지 말고 이유를 묻거나 사용자에게 알린다.
2. **검사**: 샌드박스 밖에서 `tools/check.sh`를 직접 돌린다(종료 코드 0, "resources still in use" 없음).
3. **렌더**: `tools/capture_view.gd`로 직접 다시 찍어 눈으로 본다(Codex가 남긴 PNG만 믿지 않는다). 그림 루프 작업이면 그 회차 폴더에 넣는다.
4. Codex 보고가 "통과"여도 위 셋 중 하나라도 확인하지 못했으면 커밋하지 않고, 사용자에게 그 사실을 알린다.
5. 커밋은 `git -c user.name="Claude" -c user.email="noreply@anthropic.com" commit`으로 하고, 메시지에 "Implemented by Codex; checked by the coordinator"와 실제로 확인한 것(검사 개수, 렌더 확인)을 적는다.
6. 그림의 좋고 나쁨은 승인하지 않는다(AGENTS.md §0). 렌더를 사용자에게 보여 주고 판단을 받는다. 그림 루프 작업이면 루프의 멈춤 규칙을 따른다.

## 5. 작업 메모

새로 정한 것(범위 조정, 사용자 답변)은 `notes/<브랜치>.md`에 날짜와 사용자 말 그대로 적는다.
